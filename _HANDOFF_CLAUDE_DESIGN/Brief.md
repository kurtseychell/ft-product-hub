## 1. Product summary

**Product Hub** is an enterprise SaaS backoffice that takes a product idea from initial stakeholder request through PRD generation, evaluation, prioritization, design, delivery, and release notes. AI assists at every stage under the umbrella brand **PM-BOT**.

The product is built around a clean lifecycle of versioned artifacts (Brief → PRD → Specs → Designs → Backlog Item → Release Note), with PM-BOT acting as a system actor at every AI-assisted surface.

## 2. Personas

| Persona | Primary scope |
|---|---|
| **Stakeholder** | Submits ideas, tracks own requests, consumes release notes |
| **Product Manager** | Owns PRDs, drives AI-assisted research/specs/designs, prepares engineering handover |
| **Product Lead / Domain Owner** | Reviews PRDs, scores priority, owns domain backlog |
| **Engineering Lead** | Receives handover, runs delivery, contributes to release notes |
| **QA / Tester** | Executes UAT, files bugs, performs manual bug replication when AI fails |
| **Admin** | Manages users, monitors LLM cost, configures platform |
| **Executive / Analyst** | Consumes pipeline metrics and success outcomes |
| **PM-BOT** (system actor) | Umbrella AI brand. Specialist sub-roles: PM-BOT · PRD Agent / Research Agent / Spec Agent / Design Agent / Test Agent / Release Notes Agent / Bug Replication Agent. The 3 RICE council agents (Market Analyst, Technical Feasibility, Business Strategy) keep distinct names *under* the umbrella |

## 3. Journey stages (lifecycle organised; not feature-organised)

- **A. Access** — Login, Dashboard
- **B. Stakeholder Intake & PRD Drafting** — Submit Request, PRD Builder, Tracking, Viewer, Evaluation
  - **B-Bug sub-pipeline** — Reproduction Steps Document, AI Replication, Manual Replication (TBD screens — see Regeneration_Prompts.md)
- **C. AI Processing** — Research & Analysis, RICE Scoring (3-agent council), SpecKit, Figma Design Generation
- **D. Prioritization & Planning** — Backlog (Kanban), Domain Backlogs (with comparison), Quarterly Roadmap, Tech Handover Package
- **E. Delivery & Operations** — Delivery (Sprint), UAT Testing, Release Notes Editor, Success Metrics
- **Z. Admin** — LLM Usage & Costs

## 4. Lifecycle artifacts (six)

Each artifact has a state machine surfaced in the UI as status badges and version numbers.

1. **Brief** — Stakeholder seed text. States: `v1 Draft → v1 Submitted → v1 Locked for Review` (Stakeholder may fork v(N+1) in parallel; explicit supersession prompt required)
2. **PRD Document** — Generated by PM-BOT · PRD Agent. States: `Draft (vN) → In Review → Approved → Final (vN) → Archived`. Carries a **Submission Score** (0–100) signalling readiness for product team review.
3. **Reproduction Steps Document (RSD)** — Bug-path analog of PRD. States: `Draft → In AI Replication → { Replicated by AI | Replication Failed → In Manual Replication → { Reproduced | Cannot Reproduce } } → Triaged`
4. **Spec Items (SpecKit)** — Per-PRD specs typed as `API / Data Model / UI Component / Business Logic / Integration`. States: `Draft → In Review → Approved → Needs Revision`. Carries **AI Confidence** (High/Med/Low) signalling Definition of Ready for engineering.
5. **Design Screens** — States: `Generating → Draft → Reviewed → Approved → Pushed to Figma`. Multiple variants per screen.
6. **Backlog Item / Task** — Carries `Type ∈ {Feature, Bug}`. States: `New → Under Review → Approved → In Development → Released`. Cross-cutting attributes: RICE Score (Features) or Bug Severity Score (Bugs), Domain Priority flag, Research Recommendation.
7. **Release Note** — States: `Draft → Scheduled → Published`. Channels: Email / Slack / In-App / Confluence. Audiences: Internal / External / Engineering.

## 5. Cross-persona handoffs (the failure-prone moments)

| # | From | To | Trigger |
|---|---|---|---|
| H1 | Stakeholder | PM | Submit Request (Idea/Change) → PRD Builder opens with Brief loaded |
| H2 | PM | Product Lead | Mark PRD as Final → appears in PRD Evaluation queue |
| H3 | Product Lead | PM | Approve / Request Revisions → routes back to PRD Builder or forward to RICE |
| H4 | PM | Product Lead | Approved PRD ready → RICE Scoring → Backlog |
| H5 | Domain Owner | PM | Commit to Next Sprint Cycle → handover package starts |
| H6 | PM | Engineering Lead | Send Handover (PRD + Specs + Designs + APIs + Acceptance) |
| H7 | Engineering Lead | QA | "Ready for Demo & UAT" |
| H8 | QA | Engineering Lead | Bug filed during UAT (loops via Stage B-Bug) |
| H9 | PM | Stakeholder + Customers | Publish Release Notes (notifications fire) |
| H10 | Stakeholder | PM-BOT · Bug Replication Agent | Submit Request (Type=Bug) → auto RSD draft |
| H11 | PM-BOT · Bug Replication Agent | QA / Engineer | AI replication failed → Manual Replication |

## 6. Design System (canonical, decided 2026-04-19)

### 6.1 Brand
- **Product brand:** Product Hub. Replaces 8+ alternates seen in screens (Kinetic Luminary, Architect Intelligence, Precision Curator, Enterprise Hub, Product Console, Product Admin, Product Ops, SaaS PM Backoffice).
- **AI brand:** PM-BOT (umbrella) with specialist sub-roles per surface. The 3 RICE council agents keep distinct names *under* the umbrella.

### 6.3 Typography
- **Body / Label:** Inter (weights 400, 500, 600, 700, 800)
- **Headline:** Manrope (weights 500, 600, 700, 800)
- **Drop entirely:** IBM Plex Sans (currently used on `[C02]`, `[Z01]`, `[E04]` — these are being regenerated)

### 6.4 Border radius (Material 3 scale)
| Token | Value | Usage |
|---|---|---|
| `default` | `0.125rem` (2px) | Subtle rounding on inputs, small chips |
| `lg` | `0.25rem` (4px) | Buttons, list items |
| `xl` | `0.5rem` (8px) | Cards, panels |
| `2xl` | `0.75rem` (12px) | Hero cards, larger surfaces |
| `full` | `9999px` | Pills, badges, avatars |

### 6.5 Component conventions

- **Stat / KPI cards:** white card with rounded corner; small accent-colored trend badge (top-right); large numerical value; label in caps with letter-spacing
- **AI workspaces:** 3-panel layouts (source-of-truth left | AI chat center | live document right). B02 PRD Builder is the canonical example. Always show version badges (v1, v3, v9 Final).
- **Tables:** zebra-striped or hairline-divided rows; column headers in caps with letter-spacing; columns tagged with Material Symbols Outlined icons; row hover reveals action icons
- **Status badges:** pill shape (`rounded-full`); color-coded by status family (emerald=success, amber=warning, red=critical, slate=neutral, blue=in-progress, purple=special)
- **Sidebars:** dark navy (`#1E1B4B`); inactive items white at 50% opacity; active items white text + 10% white background overlay
- **Right slide-out panels:** 500px wide for evaluation/detail panels (e.g., `[B05]`); 320–380px for compact context sidebars (e.g., `[D04]`)
- **Icon library:** Material Symbols Outlined throughout; `font-variation-settings: 'FILL' 1` for filled active state
- **Cards & elevation:** soft shadows — `shadow-sm` for subtle, `shadow-[0px_12px_32px_rgba(17,28,45,0.06)]` for prominent cards, `shadow-2xl` for modals/overlays
- **CTAs:** primary CTAs use `bg-primary` with `text-on-primary`; gradient buttons use `bg-gradient-to-r from-primary to-primary-container` for emphasis; pressed state via `active:scale-95`

### 6.6 Tone & UX principles

- **Stakeholder-facing screens are minimal-friction.** B01 has just title + brief + optional attachments. Don't ask Stakeholders to taxonomize their requests upfront — let PM-BOT infer.
- **AI-assisted screens follow the source-AI-output triptych.** B02, C01, C03, E02 all use this pattern. Anything new that involves AI generation should adopt it.
- **Versioning is first-class.** Every artifact carries a visible version badge (v1, v3, v9 Final). Locked states are explicit ("Locked for Review").
- **Status pipelines are horizontal steppers** on tracking screens (`[B03]` is the example). Show all stages; highlight current with active animation.
- **AI is explicit.** PM-BOT-driven elements always have the `auto_awesome` (sparkle) icon and either a "PM-BOT" branded header or an "AI" pill.
- **Decisions are explicit and auditable.** Approve/Request Revisions/Reject buttons require rationale. Manual overrides require audit notes.
